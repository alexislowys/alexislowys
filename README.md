## 🚀 Featured Projects

<details open>
<summary><b>⚡ cudf-bench — GPU Performance Investigation (NVIDIA RAPIDS cuDF)</b></summary>
<br/>

Benchmark harness that found a real performance defect in NVIDIA's GPU dataframe library: hash groupby aggregations run **~1.5× slower on skewed keys** while pandas and Polars get *faster* on the same input.

| | |
|:---|:---|
| **Stack** | Python · pandas · Polars · cuDF (RAPIDS) · Numba CUDA · Google Colab (T4) · pytest · GitHub Actions |
| **Architecture** | Pluggable backend adapters, deterministic data generation with a skew knob, warm-up + GPU-sync + median timer, CLI runner, speedup reports |
| **Scale** | 112-configuration grid: 3 backends × 1M/10M/30M rows × operations × key-skew levels |
| **Performance** | Isolated a 1.48× skew penalty at locked GPU clocks; Numba shared-memory prototype **2.47× faster than cuDF** on the skewed case (identical results asserted) |
| **Rigor** | Eliminated four false hypotheses, including a T4 DVFS clock-throttling artifact that faked earlier "findings" |
| **Impact** | Upstream issue [rapidsai/cudf#23256](https://github.com/rapidsai/cudf/issues/23256) — reproduced by a RAPIDS maintainer (NVIDIA) on GH200 the same day; kernel-level fix direction identified upstream |
| **Repository** | [github.com/alexislowys/cudf-bench](https://github.com/alexislowys/cudf-bench) |

**Key Features**
- Backend-agnostic harness proving pandas ↔ Polars result equivalence before trusting any timing
- Deterministic, skew-controllable data generation for reproducible runs
- CI on Python 3.10 / 3.12

**Engineering Challenges**
- No local NVIDIA GPU — entire GPU workflow runs on Colab T4 with results committed back to the repo
- GPU clock throttling (585→1590 MHz DVFS) silently corrupted early measurements; solved with locked-clock methodology

**Results**
- Maintainer-confirmed upstream finding with the true mechanism identified: hot-key atomic contention (hottest key = 38.4% of rows serializing millions of atomic adds on one output slot)

</details>
